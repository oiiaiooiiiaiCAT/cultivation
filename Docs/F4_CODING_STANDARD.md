# 平衡车编程规范（参考 F4）

## 1. 参考依据与适用范围

阅读的 F4 模块位于 `reference/F4/standard_tpye_c/standard_tpye_c/`：

- `bsp/boards/bsp_can.c`：板级 CAN 初始化。
- `application/CAN_receive.h/.c`：电机测量结构体、接收解码和控制量打包发送。
- `application/chassis_task.h/.c`：控制参数、结构体和任务分阶段处理。

本规范提炼这些模块的分层、数据组织和接口注释习惯，不照搬整个 F4 工程。
F4 使用 DJI 电机协议，当前项目使用 EMM-V5/X 固件；帧格式、单位和电流值不能混用。
参考工程中也有头文件定义静态发送缓冲区、忽略 HAL 返回值等写法，当前项目不采用。

## 2. 分层与职责

| 位置 | 职责 | 不应承担的工作 |
| --- | --- | --- |
| `Hardware/` | 外设初始化、命令打包、反馈解码 | LQR 控制决策、OLED 页面策略 |
| `Algorithm/lqr.*` | 状态反馈、参考值更新、限幅 | CAN 收发、RTOS 等待 |
| `Algorithm/balance.*` | 应用编排、状态构造、安全停机 | 原始 CAN 帧解析 |
| `Core/Src/freertos.c` | 任务调度与周期监测 | 大段控制算法 |
| `Docs/` | 参数、单位、调试和变更约束 | 与源码冲突的旧说明 |

保留现有目录，不为模仿 F4 而移动文件。业务代码修改 CubeMX 生成文件时放在 USER CODE 区域。

## 3. 命名、格式与接口

1. 保持当前 `Module_Action` 函数和 `Module_TypeDef` 类型命名；内部函数、缓冲区用 `static`。
2. 宏使用模块前缀和大写名称，协议码、换算系数、周期、限值不得散落在业务函数中。
3. 四空格缩进；结构体和函数花括号另起一行；字段一行一个，除紧密相关的旧字段外不随意改名。
4. 头文件使用包含保护，只放类型、常量、声明；全局对象只在一个 `.c` 中定义。
5. 公共 API 写明职责、调用上下文、参数单位和返回值含义；参数有效性在模块边界检查。
6. 硬件调用检查 `HAL_StatusTypeDef`；成功发送不等于电机成功执行，二者必须在注释中区分。
7. 无必要不修改 HAL/CMSIS/FreeRTOS 源码，不统一重排第三方代码格式。

## 4. 控制量、测量量与单位

- 参照 F4，每个电机结构体只保留控制所需的指令、位置、速度，以及保证反馈可用的有效标志和时间戳；不保存重复反馈、收发计数、应答和原始帧。
- `commandedCurrentMa` 是发送指令，不是实际电流；当前查询只提供速度和位置。
- 驱动反馈使用 rpm、deg；LQR 状态依次为位置误差 m、速度 m/s、pitch rad、pitch 角速度 rad/s。
- 命令协议边界转换 mA；LQR 的原始输出为 A，禁止将力/力矩输入模型的 K 直接用于电流输入。
- 控制任务周期与离散模型周期一致；现有增益仍需实际机械参数和方向验证。
- 单位写在字段注释或命名中；时间差使用无符号 `now - updated`，支持 tick 回绕。

## 5. 中断、任务与实时性

- CAN ISR 只取帧、校验、解码、更新时间戳，不执行 LQR、不延时、不等待发送。
- CAN 发命令只有控制任务一个调用者；初始化在调度器启动前完成，不从 OLED 任务发命令。
- `volatile` 只保证可见性，不保证多字段快照一致；任务读中断数据时用短临界区复制。
- 浮点状态换算、LQR、显示和 CAN 等待在临界区外执行。
- 等待邮箱和发送完成都有时间/循环次数边界，不允许无限忙等；正常控制路径不等待电机应答。
- 查询按固定顺序轮询，一次一项，不因等待某项回复而停止后续查询。

## 6. 安全与通信诊断

- 反馈过期：输出零电流并继续查询，不锁存 FAULT 05；反馈恢复可重新参与控制。
- 发送失败：通过 HAL 返回值交给应用层，双轮统一停机，避免一轮输出而另一轮未更新；使用既有停机重试机制。
- 发送失败停机后需重新按 START，不把这种情况冒充为自动恢复。
- 倾倒、IMU 不健康、手柄失联、超速/位移和 CROSS 急停保护保留。
- 停机先取消实际硬件邮箱中的待发帧，再停止并禁用两轮，不能依赖已停用的异步状态标志。
- 不新增 OLED 电机反馈页；反馈通过 Keil Watch 观察。

## 7. 注释与验证

- 文件头用 `@file/@brief`；接口用 `@brief/@param/@return`，局部注释解释单位、符号和特殊原因。
- 不逐行翻译代码，不粘贴装饰性大段图案或参考工程版权头。
- 删除停用功能时同时清理实现、类型、宏和调用，不保留空服务函数或不再更新的统计字段。
- 注释与文档不得承诺未验证的机械模型、实车 CAN 时序或稳定性。
- 修改后先检查差异，再执行 Keil 全量重编；编译通过不代表闭环稳定，架空车轮验证方向和急停。

## 8. 本次落实

- 移除已停用的应答确认、异步发送结构、故障快照和独立电流测试分支。
- 协议码集中定义；补充收发上下文、状态单位、限幅和反馈恢复注释。
- 控制任务短临界区采集数据，临界区外完成浮点状态转换。
- 停机检查真实 CAN 邮箱；电流发送失败不再被无条件成功返回掩盖。
- 保留电机 ID 1/2、位置/速度反馈、LQR 增益和 OLED 三个页面。
- 电机结构体只留 8 个必要成员；删除 `g_motor_bus`、`g_ps2_diag` 及重复反馈/通信统计。
- MPU 删除未使用的原始值、温度和 ID 缓存，通信配置留在单设备驱动内部；三轴融合、校准及安全字段保留。
- OLED 结构体只保留页面选择；LQR 不再保存反馈年龄数组、过程统计和重复参考步长，应用故障状态不重复存储。
- 全局结构体占静态 RAM，局部副本才占任务栈；精简时同时检查两者，不以缩减任务栈配置代替验证。
